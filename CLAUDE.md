# MarchingCubes

## MCP servers

`.mcp.json` declares two. Approve them per machine in
`.claude/settings.local.json` (`enabledMcpjsonServers`), which is gitignored.

| | |
|---|---|
| `unityMCP` | HTTP, `http://localhost:8081/mcp`. Started by the Editor, not by Claude. |
| `blender` | stdio, `uvx blender-mcp`. Needs the BlenderMCP panel connected. |

**Port 8081 is deliberate, not a default.** The `spaceGame/SpaceGame` project
runs its own MCP-for-Unity server on **8080**. Both Editors are often open at
once, and a server on 8080 here would answer with *that* project's scene — the
failure looks like a stale domain, not a misconfiguration. If a tool result
mentions the wrong project, check `Application.dataPath` before debugging
anything else.

**Do not click "Register with Claude Code"** in the MCP For Unity window. It
writes a second entry named `UnityMCP` into `~/.claude.json`, and every
`mcp__unityMCP__*` permission rule then matches only one of the two. This repo
registers from `.mcp.json` only.

The Unity server dies on domain reloads and long Editor stalls
(`remote party closed the WebSocket connection`). That is expected; `/mcp`
reconnects, and it usually recovers on its own.

### What goes through MCP

Reading the console, inspecting scenes and assets, running the Test Runner,
driving play mode. **Terrain geometry is never authored through MCP** — it is
generated by `DensityField` code and its config assets in
`Assets/TerrainGen/Config/`. Edit the field or the asset, not the resulting
mesh.
